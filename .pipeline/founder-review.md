## 2. SEO Foundation

### What Was Implemented

#### 2.1 Dynamic Sitemap (`/sitemap.xml`)

**What It Is:**
- Auto-generated XML file listing all 16 public pages
- Tells search engines which pages exist and should be crawled
- Includes priority and change frequency for each page

**Implementation:**
```typescript
// src/app/sitemap.ts
16 pages total:
- Homepage (priority 1.0, weekly)
- 3 Landing pages (priority 0.9, monthly) ← High priority for SEO
- Occasions hub (priority 0.9, monthly)
- Product pages (0.8, monthly)
- Support pages (0.6-0.7)
- Company pages (0.3-0.5)
- Legal pages (0.3, yearly)
- Status page (0.3, daily)
```

**Why It Matters:**
- **Discovery:** Without sitemap, Google may miss pages (especially new landing pages)
- **Priority signals:** 0.9 priority tells Google landing pages are important
- **Crawl efficiency:** Change frequency helps Google optimize crawl budget
- **Indexing speed:** New pages get indexed faster when in sitemap
- **Required for Google Search Console:** Can't submit pages without sitemap

**Business Impact:**
- Landing pages will be indexed within 1-7 days (vs 2-4 weeks without sitemap)
- All 12 Phase 1 pages now discoverable
- Foundation for adding 7 more occasions in Phase 2C

---

#### 2.2 Robots.txt (`/robots.txt`)

**What It Is:**
- Instructions for search engine crawlers
- Explicitly allows landing pages
- Blocks private pages (/m/, /dashboard/, /manage/)
- Points to sitemap location

**Implementation:**
```
Allow: /birthday-memory-book
Allow: /retirement-memory-book
Allow: /farewell-memory-book

Disallow: /api/
Disallow: /dashboard/
Disallow: /manage/
Disallow: /m/

Sitemap: https://memorypop.app/sitemap.xml
```

**Why It Matters:**
- **Privacy protection:** Prevents Google from indexing private MemoryPops (/m/ URLs)
- **Security:** API routes not indexed (prevents exposure of endpoints)
- **Explicit allow:** Tells Google landing pages are priority (not just "not disallowed")
- **Sitemap reference:** Ensures Google finds sitemap even if not submitted to Search Console

**Business Impact:**
- Protects user privacy (private MemoryPops never appear in search)
- Focuses Google's crawl budget on public marketing pages
- Prevents accidental indexing of dashboard/admin pages

---

#### 2.3 Canonical URLs

**What It Is:**
- Each page declares its "canonical" (official) URL
- Prevents duplicate content penalties
- Consolidates ranking signals to one URL

**Implementation:**
```typescript
// Every page layout includes:
alternates: {
  canonical: getCanonicalUrl('/birthday-memory-book'),
}
```

**Why It Matters:**
- **Duplicate content:** Without canonical, `/birthday-memory-book` and `/birthday-memory-book?utm_source=google` are treated as separate pages
- **Parameter handling:** UTM tracking parameters don't dilute SEO (signals consolidated to canonical)
- **HTTPS/WWW:** If accessible via multiple domains, canonical prevents split ranking
- **Required best practice:** Google expects canonical tags on all pages

**Business Impact:**
- All organic traffic value flows to one URL (not split across parameters)
- No duplicate content penalties
- Tracking parameters work without SEO penalty

---

#### 2.4 Event Schema (Structured Data)

**What It Is:**
- JSON-LD structured data on landing pages
- Tells Google this is an "Event" that users can participate in
- Includes price ($0), location (online), organizer (MemoryPop)

**Implementation:**
```json
{
  "@type": "Event",
  "name": "Birthday Memory Book Creation",
  "eventAttendanceMode": "OnlineEventAttendanceMode",
  "eventStatus": "EventScheduled",
  "offers": {
    "price": "0",
    "priceCurrency": "USD"
  }
}
```

**Why It Matters:**
- **Rich results:** May show "Free" badge in search results
- **Event listings:** Could appear in Google Events search
- **Trust signals:** Structured data shows Google we're legitimate
- **Click-through rate:** Rich results get 30%+ higher CTR than plain results

**Business Impact:**
- Landing pages may get enhanced search appearance
- "Free" price shown inline (removes cost objection before click)
- Increased CTR from organic search
- Foundation for future Product schema if we add physical keepsakes

**When It Fires:**

- Measure top-of-funnel traffic volume
- Baseline for conversion funnel
- Compare homepage traffic vs landing page traffic over time

**Business Question It Answers:**

Expected Insight: As SEO improves, landing page traffic should grow faster than homepage traffic (direct channel indicator).

**Parameters:**
- `page_title`: "MemoryPop - Create Beautiful Online Memory Books"

### Event 2: `landing_page_viewed`

**When It Fires:**
- User visits any occasion landing page
- Fires on page load
- Includes occasion name and traffic source

**Why It Exists:**
- Measure organic acquisition by occasion
- Understand which occasions drive most SEO traffic
- Calculate landing page → create conversion rate

**Business Question It Answers:**

**Parameters:**

### Event 3: `create_started`

**When It Fires:**
- User begins creating MemoryPop (Step 1 of creation flow)
- Fires when first interaction occurs
- Includes source attribution

**Why It Exists:**
- Measure landing page → create conversion
- Attribute conversion to traffic source
- Calculate drop-off between view and create

**Business Question It Answers:**
"What percentage of landing page visitors start creating? Which traffic sources have highest intent?"

Expected Insight: Landing page visitors should have 15-25% create start rate (vs 5-10% homepage baseline). Validates landing pages driving qualified traffic.

**Parameters:**
- `source`: "homepage" | "landing_page_birthday" | "landing_page_retirement" | "landing_page_farewell" | "direct"
- `occasion`: Selected occasion (pre-filled from URL or user-selected)
- `page_location`: /create URL

**Source Attribution Logic:**
```typescript
const referrer = document.referrer;
let source = 'direct';
if (referrer.includes('birthday-memory-book')) {
  source = 'landing_page_birthday';
} else if (referrer.includes('retirement-memory-book')) {
  source = 'landing_page_retirement';
} else if (referrer.includes('farewell-memory-book')) {
  source = 'landing_page_farewell';
}
```

**Why This Matters:**
Attribution connects landing page traffic to actual conversions. Without this, we'd know landing pages get traffic but not whether they convert.

### Event 4: `create_completed`

**When It Fires:**
- User successfully creates MemoryPop (final step complete)
- After API returns success
- Fires once per creation

**Why It Exists:**
- Primary conversion event
- Measure landing page → conversion funnel
- Calculate cost per acquisition (when we add paid acquisition)

**Business Question It Answers:**

**Parameters:**
- `share_code`: Unique MemoryPop ID (for funnel analysis)
- `occasion`: Selected occasion
- `from_landing_page`: boolean (true if came from SEO landing page)
- `conversion`: true (marks as conversion event in GA4)

**Landing Page Flag Logic:**
```typescript
const referrer = document.referrer;
const fromLandingPage = referrer.includes('birthday-memory-book') ||
  referrer.includes('retirement-memory-book') ||
  referrer.includes('farewell-memory-book');
```

**Why This Flag Matters:**
Separates organic acquisition conversions from other channels. Tells us: "Of all conversions today, how many came from SEO?" Critical for Phase 2B/2C ROI calculation.

## 4. Create Flow Integration

### How ?occasion= Parameter Works

**URL Structure:**
```
/create?occasion=birthday
/create?occasion=retirement
/create?occasion=farewell
```

**Implementation Flow:**

**Step 1: Landing Page CTA Click**
```tsx
// Birthday landing page
<Link href="/create?occasion=birthday">
  Create Your Birthday MemoryPop →
</Link>
```

User clicks CTA → navigates to `/create?occasion=birthday`

---

**Step 2: Create Page Reads URL Parameter**
```typescript
// src/app/create/page.tsx (lines 13-32)

const searchParams = useSearchParams(); // Next.js hook
const urlOccasion = searchParams.get('occasion'); // Reads "birthday"

// Map URL slugs to display names
const occasionMap: Record<string, string> = {
  'birthday': 'Birthday',
  'retirement': 'Retirement',
  'farewell': 'Farewell',
  'wedding': 'Wedding',
  'anniversary': 'Anniversary',
  'new-baby': 'New Baby',
  'graduation': 'Graduation',
};

// Pre-select occasion if valid, otherwise default to "Birthday"
const initialOccasion = urlOccasion && occasionMap[urlOccasion.toLowerCase()]
  ? occasionMap[urlOccasion.toLowerCase()]
  : "Birthday";

// Set as initial state
const [occasion, setOccasion] = useState(initialOccasion);
```

---

**Step 3: Occasion Dropdown Pre-Filled**
When page renders:
- Occasion dropdown shows "Birthday" (pre-selected)
- User can change if desired
- No forced selection (user maintains control)

---

**Step 4: User Completes Creation Flow**
- Step 1: Occasion (pre-filled from URL)
- Step 2: Mood (user selects)
- Step 3: Personal message (user writes)
- Step 4: Preview and create

---

**Step 5: Analytics Attribution**
```typescript
// When user starts creating:
const referrer = document.referrer;
let source = 'direct';
if (referrer.includes('birthday-memory-book')) {
  source = 'landing_page_birthday';
}

trackCreateStarted(source, occasion); // GA4 + Mixpanel

// When user completes:
const fromLandingPage = referrer.includes('birthday-memory-book') || ...;
trackCreateCompleted(shareCode, occasion, fromLandingPage);
```

Attribution flows through entire funnel:
- Landing page → Create start → Create complete
- Enables calculation: "Birthday landing page drove 45 conversions this month"

### Attribution Chain

**Without ?occasion= parameter:**
- User searches → Landing page → Creates
- We know landing page was viewed
- We know MemoryPop was created
- We DON'T know if they're the same user (can't connect events)

**With ?occasion= parameter:**
- User searches → Landing page → `/create?occasion=birthday` → Creates
- Referrer analysis: `document.referrer` includes "birthday-memory-book"
- `create_started` event: `source: landing_page_birthday`
- `create_completed` event: `from_landing_page: true`
- Attribution complete: We know this conversion came from Birthday landing page

**Why This Matters:**
- Calculate conversion rate per landing page
- Understand which occasions drive best traffic
- Optimize underperforming pages
- Justify scaling to 7 more occasions (or not)

---

### Edge Cases Handled

**Case 1: User removes ?occasion= from URL**
- initialOccasion defaults to "Birthday"
- User can manually select any occasion
- No error, graceful fallback

**Case 2: User types invalid occasion (?occasion=foobar)**
- occasionMap doesn't include "foobar"
- Defaults to "Birthday"
- No error, graceful fallback

**Case 3: User bookmarks /create (no parameter)**
- Works normally, no pre-fill
- User selects occasion manually
- Source attribution: "direct" (not from landing page)

**Case 4: User navigates from homepage to /create**
- No ?occasion= parameter
- Source attribution: "homepage" (from referrer analysis)
- Not counted as landing page conversion

**Case 5: User shares `/create?occasion=retirement` link directly**
- Occasion pre-fills correctly
- Source attribution: "direct" (not from our landing page)
- Still works, just not counted as landing page conversion

### As a UX Designer

**Strengths:**
✅ Clear user journey (problem → solution → how → examples → FAQ → action)
✅ No dead ends (every section has clear next step)
✅ FAQs remove objections (cost, privacy, blank page anxiety)
✅ Occasion parameter pre-fills form (reduces friction)
✅ Internal linking strategy (explore more after conversion)

**Weaknesses:**
⚠️ **5-step "How It Works" too long:** Users won't read all 5 steps
  - Impact: Information overload
  - Recommendation: Reduce to 3 steps (Start → Collect → Share)

⚠️ **FAQ buried at bottom:** Users may leave before seeing objections removed
  - Impact: Preventable drop-off
  - Recommendation: Add "Questions?" dropdown above first CTA

⚠️ **No urgency:** Nothing tells user "do this now" vs "do this eventually"
  - Impact: User leaves, never returns
  - Recommendation: Add "Most popular for [upcoming occasion]" or "Create in under 2 minutes"

⚠️ **CTA only appears twice:** Hero + final section
  - Impact: Mid-page readers have to scroll to convert
  - Recommendation: Add sticky CTA bar on mobile

⚠️ **No exit-intent:** User leaving without converting? No capture
  - Impact: Lost visitors
  - Recommendation: Add exit-intent popup ("Wait! See a real MemoryPop first")

**Recommendations:**
1. Simplify "How It Works" to 3 steps
2. Add FAQ accordion earlier in page (after Why section)
3. Add urgency trigger ("Created by 1,000+ people this month")
4. Add sticky mobile CTA bar
5. Add exit-intent capture (email or demo view)
